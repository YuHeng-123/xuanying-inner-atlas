# 命理三式解读与人际关系档案

这是一个本地优先的参考工具，包含八字结构解读与大运流年、紫微斗数与动态运限、十二星次现代体验内容，以及关系合盘与避险记录。传统术数部分按项目公开的历法约定计算；关系分数和十二星次人格/配对文案属于启发式或原创体验，不是经过科学验证的心理测评或现实预测。

## 环境要求

- Python 3.11 或更新版本
- Node.js 18.17 或更新版本（建议使用当前受支持的 LTS）
- npm

## 本机启动

在项目根目录打开两个终端。

终端一启动后端：

```powershell
python -m venv .venv
./.venv/Scripts/Activate.ps1
python -m pip install -r backend/requirements.txt
Copy-Item backend/.env.example backend/.env
uvicorn backend.main:app --reload --port 8000
```

终端二启动前端：

```powershell
if (!(Test-Path frontend/.env.local)) { Copy-Item frontend/.env.example frontend/.env.local }
cd frontend
npm ci
npm run dev
```

打开 <http://127.0.0.1:3000>。后端健康检查为 <http://127.0.0.1:8000/healthz>，交互式 API 文档为 <http://127.0.0.1:8000/docs>。

若本机 8000 端口已被其他服务使用，可把后端命令中的端口改为 `8010`，并在 `frontend/.env.local` 设置 `NEXT_PUBLIC_API_BASE_URL=http://127.0.0.1:8010`，随后重新启动前端。当前工作区因 8000 端口冲突使用这套本机配置；它不会改变 `frontend/.env.example` 的默认值。

如果 PowerShell 阻止激活虚拟环境，可直接执行 `./.venv/Scripts/python.exe -m pip install -r backend/requirements.txt`，再用 `./.venv/Scripts/uvicorn.exe backend.main:app --reload --port 8000` 启动。

## 模型配置

后端读取 `backend/.env` 中的 `LLM_API_KEY` 或兼容的 `OPENAI_API_KEY`。两者留空时使用本地 Mock 报告；可选配置 `LLM_BASE_URL`、`LLM_MODEL`、`LLM_TIMEOUT_SECONDS`。不要把真实密钥提交到版本库，也不要将 `.env` 内容贴入问题或日志。

关系备注在配置模型密钥时会随研判请求发送至配置的模型服务；不要填写身份证号、联系方式、住址或其他敏感信息。出生资料用于本地后端排盘；关系档案默认保存在当前浏览器的 localStorage。

## 跨设备访问与部署

`frontend/.env.example` 中的 `http://127.0.0.1:8000` **仅供前端和后端运行在同一台电脑上的本机开发**。若用手机或其他电脑打开前端，浏览器中的 `127.0.0.1` 指向访问者自己的设备，不是运行 FastAPI 的电脑。

要保留私有源码并发布公开网页，按 [部署说明](DEPLOY.md) 使用 GitHub Private、Vercel 和 Render。

部署时，在构建前设置：

```text
NEXT_PUBLIC_API_BASE_URL=https://api.example.com
```

该值填写后端 origin，不要附加 `/api/v1`；代码会追加接口路径。`NEXT_PUBLIC_*` 会打包进前端静态资源，修改后要重新构建并部署前端。后端需能从访问者浏览器所在网络访问，并将前端站点来源配置到 `CORS_ORIGINS`（逗号分隔）。公开部署应使用 HTTPS，并避免把开发用的 `CORS_ORIGINS=*` 当作生产安全策略。若前后端经同一反向代理提供，可填写前端 origin（如 `https://app.example.com`），并让代理转发 `/api/v1/*` 到 FastAPI。

## 排盘口径

- 用户输入公历日期；后端按中国标准时间 UTC+8 计算。
- 八字年柱以立春为换年边界，月柱以节气换月；日界采用 23:00 子初换日。
- 默认不校正真太阳时。只输入出生小时、没有分钟而恰逢节气交界时，相关星次候选并列显示。
- 八字“大运流年”使用 `lunar-python` 的 `getYun(..., sect=1)` 计算起运和运年序列；计算时需要选择本次排盘口径。档案没有出生时辰时，用户需临时选择代表时刻；这些临时参数不会写入个人档案。起运时刻按所选整点估算，节气交接附近仍可能受出生分钟影响。
- 八字流月按 `lunar-python` 返回的流年流月序列展示十二个节气月，寅月为第一月；每月起止时刻取库内节气表并按中国标准时间显示，不等同于公历自然月或农历月份。紫微流月按 `iztro.monthlyList` 的农历月份显示；闰月依 iztro 默认规则拆为前后两段，并展示各段农历日期范围、宫位、四化与流曜。两种流月遵循不同历法口径。
- 八字岁运计算按中国标准时间定位当前节气月；计算当前流年时若当前时间仍在该年立春之前，则回退到上一流年。流月详情会并列展示本命四柱、所选大运、流年、流月，并汇总这七个位置之间按项目规则识别的六合、六冲、六害与刑关系；每条关系标出涉及位置，只呈盘面依据，不据此判断吉凶。
- 紫微“大限与流年”使用 `iztro` 当前默认运限配置；按所选公历年份的 6 月 1 日读取动态盘，只列干支、落宫、四化和流曜，不自动生成吉凶断语。不同流派的运限分界和解释可能不同。
- 未知出生时辰不会伪装成准确时柱：关系页保留六字参考盘，并额外展示规则假设下的相对有利端和谨慎端。
- 十二星次体验按项目选择的节气边界映射；历史上的十二次是天文分区，不等同于古代生日人格体系。人格与配对内容为现代原创表达。
- 关系五维和风险等级是透明的产品规则分数，不是临床心理诊断、客观概率或对他人行为的事实判断。

## 本地档案、备份与恢复

个人基准、关系历史和互动笔记分别保存在当前浏览器的 `my_bazi_profile`、`relationships_history`、`relationship_events` 中。清除浏览器数据或换浏览器/设备不会自动同步这些记录。

问卦包含四种本地方式：日常选择会在 2–4 个非空选项中等概率抽取；圣杯掷筊按两枚杯的平面/凸面组合显示圣筊、笑筊或阴筊；签筒从 24 条原创反思提示中抽取，每种签级各 6 条，因此四种签级在当前体验中机会相同，这不是寺庙传统签谱；铜钱六爻以花面计 3、字面计 2，从初爻开始掷六次并计算本卦、变卦和动爻。随机结果在动画开始前生成，动画展示同一份结果。

新保存的占卜记录会保留选项、杯面、签号与提示内容，或六爻数值，点开本机记录可以重新查看过程；旧版记录仍可查看原有问题和结果摘要。占卜记录也包含在 v2 JSON 备份中。

关系时间线可补记过去的互动时间、事实和自己的感受；页面展示最近五条记录的感受分布，并支持按感受筛选。该分布只反映手动记录，不参与八字分数计算。此功能参考了 [Monica 的互动记录与活动时间线](https://github.com/monicahq/monica) 这一产品思路，界面与代码在本项目中独立实现。

在“档案管理”中使用“导出 JSON”备份。恢复时选择备份文件后，可合并或替换关系记录，并选择是否恢复本人底牌。替换会覆盖当前关系档案，建议先导出一份现状备份；导入前会校验文件结构。分享海报不展示出生年月日。

历史关系记录会保留分析时的本人出生资料快照。以后修改底牌不会改写旧报告；如果排盘生日或时辰发生变化，页面会标记旧底牌报告，需重新测算才会生成新结果。

## 检查与测试

从项目根目录运行后端单元与 API 合约测试（API 测试会显式清空测试进程中的 LLM Key，仅验证 Mock，不会调用外部模型）：

```powershell
python -m unittest discover -s backend -p "test_*.py"
```

从 `frontend` 目录运行前端测试、类型检查、Lint 与生产构建：

```powershell
npm run test
npm run typecheck
npm run lint
npm run build
```

开发服务器和生产构建会共享 Next.js 输出目录 `.next`；验收生产构建前先停止同一前端目录下的开发服务器，完成后再重新启动。
